# XNote

[简体中文](README.zh-CN.md) · [Architecture](docs/architecture.md) · [Validation](docs/validation.md) · [Copyright and permissions](COPYRIGHT.md)

A local desktop notebook combining Markdown, document annotations, spaced repetition and optional AI assistance.

XNote is a personal learning project, currently version **0.1.0**. It is useful for keeping course notes and imported reading material in one library, annotating them, and revisiting whole documents with FSRS scheduling.

## Features

- Folder-based library: create Markdown notes, import files, rename/move items and restore them from trash.
- CodeMirror live Markdown preview with source mode, search/replace, tables, code highlighting, math, Mermaid and resizable images. Pasted images are grouped in a dedicated attachment folder.
- In-app PDF, DOCX, image, spreadsheet/CSV and text viewers. Unsupported formats can be opened with a system application.
- Text highlights, underlines, comments, region annotations and freehand drawing where the viewer supports them. Annotations live separately from the original files.
- Whole-document FSRS review, four ratings, reflections, parameter groups inherited from folders, exam dates and daily time/count budgets.
- Optional AI library search and multi-conversation questions, current-document context, citations and tool steps. Adapters exist for OpenAI, DeepSeek, Anthropic and Google; model availability must be checked with the chosen service. Mock mode works without a key.

## Requirements

Validated locally: **Windows 11 x64**, **Node.js 22.23.2**, **npm 10.9.8**, locked **Electron 33.4.11**. `.nvmrc` records the tested Node version. Other operating systems and architectures are unverified; packaging is configured for Windows.

Install Git and Node.js with npm. Installation needs internet access to npm, Electron downloads and native-module downloads. If a native prebuilt binary is unavailable, Python 3 and Visual Studio Build Tools with C++ support may be needed. All other application dependencies are declared in the lockfile; do not install global application packages.

## Quick start

The following installation, usage and development instructions are for the owner and users with prior written permission. Public access does not authorize running or modifying the software; see [copyright and permissions](COPYRIGHT.md).

```powershell
git clone https://github.com/Sean-xzx/note-tracker-XNote.git
cd note-tracker-XNote
npm ci --no-audit --no-fund
npm run rebuild
npm run dev
```

`rebuild` targets the SQLite native module at Electron's ABI. Repeat it after reinstalling dependencies or changing Electron. See the [Electron native-module guide](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules).

Success means an XNote desktop window appears with the file library, review navigation and settings. A fresh profile is empty. No database download or API key is needed to create, edit, annotate and review notes.

For a built local application:

```powershell
npm run build
npm start
```

On Windows, `启动XNote.bat` also launches from its own directory, building first if the output entry is missing. It requires the installation and rebuild steps above.

## Representative example

1. Create a folder and a Markdown note. Paste:

```markdown
# My first review

Local notes are searchable.

- [ ] Recall this idea tomorrow
```

2. Wait for the saved status, switch notes and reopen: the text should remain. New Markdown notes enter today's review; ordinary imported files start unscheduled until added to review.
3. Switch to annotation mode, select “Local notes” and add a highlight. It should appear in the annotation sidebar and survive a restart.
4. Open today's review, recall the content, read it, choose one of the four ratings and optionally write a reflection. History should contain the rating; the next interval is at least one day.
5. For a free AI demonstration, select **Mock** in settings, disable web search and ask `总结《My first review》`. Expect a clearly labelled simulated answer, not a real model-generated interpretation.

The automated counterpart uses isolated temporary data and prints `ALL VERIFICATION CHECKS PASSED` on success.

## Configuration and resources

There is no required `.env`. Configure optional providers and models in the settings UI. Real chat, embeddings, vision and web search need applicable service keys and connectivity and may incur provider charges. They are not called by the offline tests. Choose models currently offered by your service; preset model names are not a compatibility promise.

Chat and embedding providers can differ. Real vector embeddings are supported by the OpenAI/Google adapters; otherwise search/indexing can use keywords. Mock is for functional demonstration. Index the library in settings when semantic retrieval or image descriptions are needed. Scanned PDFs do not have an implemented OCR pipeline.

Application data is under Electron `userData` (normally `%APPDATA%/xnote` on Windows): `xnote.db`, `notes/`, `files/`, `ai-settings.json` and `ai-keys.enc`. Some UI preferences use local storage. Back up the entire profile with the application closed; a database-only backup does not include note/file bytes. Importing copies files into the library. Visible folders are database relationships, not mirrored filesystem directories.

Keys use Electron `safeStorage` when available; the fallback encoding is not encryption. Settings report encryption availability. Never commit a profile, key file or personal export. Source-checkout runs normally use the same profile as other XNote runs; only `npm test` guarantees a fresh isolated test profile.

## Structure and collaboration between modules

```text
src/main/        Electron lifecycle, SQLite, files, FSRS and AI requests
src/preload/     Explicit window.api bridge and shared types
src/renderer/    React UI, CodeMirror and document viewers
assets/brand/    Application icons and brand resources
tests/          Offline Electron runtime and attachment regressions
scripts/        Test runner and publication checks
docs/           Architecture, validation and resource notices
.github/        Windows verification workflow
```

The package entry is `out/main/index.js`, built from `src/main/index.ts`. The renderer starts at `src/renderer/src/main.tsx`. UI requests travel through preload → IPC → main services; SQLite stores metadata, annotations, review history and chats, while disk files hold document bytes. `notes.ts` supplies the shared item IDs used by viewers, review and AI. See [architecture](docs/architecture.md).

## Verification and packaging

After installation and native rebuilding:

```powershell
npm run verify
npm run pack:dir -- --config.win.signAndEditExecutable=false
npm run test:package
```

`verify` checks publication files and documentation links, checks both TypeScript layers, builds all layers and runs real Electron tests. Tests cover persistence, Markdown import bytes, plain text edits, annotations, review, invalid moves, trash restore, offline AI/indexing and attachment layout. They retain temporary profiles for diagnosis and write ignored logs/screenshots under `test-results/`; failures exit nonzero.

`pack:dir` creates an unpacked app in `release/win-unpacked`. The verification override skips signing/executable resource editing to avoid a Windows symbolic-link privilege requirement; the Explorer executable icon may remain Electron's default, while in-app brand resources are retained. Full branded executable packaging with `npm run pack:dir` or `npm run dist:win` may require permission to create symbolic links (for example an appropriately configured build machine). `dist:win` requests NSIS and portable executables. No prebuilt installers are included in the repository; signing, installer execution and other-platform packaging are not part of the verified minimum. Windows CI uses the documented override. Exact results are recorded in [validation](docs/validation.md).

## Troubleshooting and limitations

- Native-module/ABI error: run `npm run rebuild`, then retry; check build prerequisites if downloading a prebuilt module fails.
- Source changes missing in a built run: rebuild `out/` or use `npm run dev`.
- AI key/model/network failure: verify the provider in settings, select an available model, or use Mock with web search off.
- DOCX is converted to reading HTML; spreadsheets are viewers capped at 2,000 displayed rows. XNote is not a full Office editor.
- Review schedules whole documents; per-highlight review is not implemented. “Current file” focuses AI context but does not disable its library tools.
- Changing embedding models can leave old content-hash-based index entries: clear the index before rebuilding with a new model.
- No implemented cloud sync, scanning OCR or guaranteed compatibility with every file/provider. The existing Electron/toolchain versions are retained; this publication is not a dependency/security modernization.
- The retained production dependency tree has 14 npm audit vulnerability entries (1 critical, 4 high, 3 moderate, 6 low) as of 2026-10-08. This is a functional project release, not a security-hardened distribution; see the validation record. Audit counts do not establish exploitability in every application path.
